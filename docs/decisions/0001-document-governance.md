# ADR-0001 文档治理与开发流程

- 日期：2026-10-07
- 状态：superseded；当前规则见 [ADR-0002](0002-workspace-foundation.md)，本文保留历史决定
- 范围：工作流程与文档职责，不代表应用能力已实现

## 决定

保留既有需求、设计和标准路径；新增开发入口、文档登记、工程规则、沟通协议、交付状态和模板。每类事实一份正本；用户事项只在 USER-ACTIONS，开发后续只在状态页。

采用规划—执行—审查职责与连续执行、集中处理用户事项的方式。默认一个阶段一个本地交付提交，远端已推送历史不自动改写；本次初始化按用户要求保留两个提交。

参考工程索引放在仓库父级 reference 体系，仓库只记录可移植的发现方式和边界。公开必要的实现依赖和许可证来源仍须保留。

## 取舍与验证

不移动现有需求/设计，减少链接迁移与重复正本；不复制与本项目无关的产品决定、UI 主题、许可证或既有验收结论。建立 Python 标准库检查器和 CI，使登记和链接规则可以执行。

机械检查只覆盖结构，标准解释、实现正确性、授权和人工体验仍由对应证据与审查判断。
