准备时已视觉核对 PDF 23、24、36、37、88、92、97、98、145、152。字符集 6.10、9.5.1/9.6.2—3、A.2.1 公共字段/目录项、附录 E/J 及 RFC 事务/认证的实际 M0 实施补审范围见原实施报告；2026-10-11 再对照两版 OCR 并回到关键 PDF 原页。不能把已审 M0 子集当作全字段 Schema 已完成。标准模式的 GB18030 和最终字节 Content-Length 要求保留。

发现并处理的易错点：

- Keepalive 的 XML 根为 Notify，但 SIP 方法为 MESSAGE；不能因此发送 SIP NOTIFY。
- DeviceInfo 与 Catalog 的业务 Response 是新的 SIP 请求，不是查询事务的 200 正文。SIP 成功、业务成功、状态观测分别保存。
- Catalog 空结果不应习惯性生成空 DeviceList；附录 M 明确不携带记录列表。多批总数和本批 Num 分开。
- DeviceInfo 的 Channel 是可选非负整数；不要把截图上的“通道 01”当作这个字段值。
- A.2.5.2 的 Info 元素本身未写 minOccurs=0，内部 DeviceID 为零到多个；9.6.1(c) 对故障子设备信息用“宜”。M0 正常向量可保留空 Info，并在实现规则中说明选择，不能根据 OCR 省略标签。
- 图中协议片段和条款号均为示意；页面引用必须来自已审核条款，不能照抄参考图。

## 2. 字段与状态契约

SIP 传输/事务适配 sipgo，业务规则由 Lab 自己实现。RFC 3261 第 10、17、18、22 节、RFC 3428 MESSAGE 和 RFC 3581 rport 的 M0 核对及向量见实施报告；[RFC 3261](https://www.rfc-editor.org/rfc/rfc3261)、[RFC 3428](https://www.rfc-editor.org/rfc/rfc3428)、[RFC 3581](https://www.rfc-editor.org/rfc/rfc3581) 是原文入口。2026-10-11 重新取得 RFC3261 官方文本，字节与已有本地证据一致。

1. ID 保持 20 位字符串；注册设备、通道、目标系统的身份关系按附录 E/J 定义，不把通道自动当作独立注册主体。端点和 SIP URI 的身份/realm 分离。
2. 内置平台支持 Digest，nonce 不可预测且有生命周期，认证错误不创建绑定。明确 MD5 legacy/qop=auth 支持范围、realm、uri、nonce/nc/cnonce/opaque/stale、CSeq 和合法重传去重；不把 MD5 Digest 宣称为 GB35114。由原文和独立向量确定参数，不套用 Web 登录密码。
3. 事务重传保留原 branch/CSeq/字节；新事务遵循序号规则。注册、业务 SN 和 operationId 分开，响应来源与当前绑定关联；晚到响应不得使已注销/已取消代次复活。
4. UTF-8 用于管理 API，SIP 编码规则用 GB18030；XML 声明与真实编码一致，Content-Length 按最终 body 字节计算。覆盖中文、四字节字符、XML 转义、CRLF、非法编码、重复 Content-Length、截断和超长消息。
5. 入站先保留受控原始字节，再解析。日志/前端展示脱敏副本，展示格式化不能覆盖原文。未知方法/CmdType、错误根节点、重复必选字段、SN/ID 错误明确失败，不能成功驱动状态。
6. 注册成功才进入正常心跳；收到超时/拒绝后更新该绑定原因和计时；停止先阻止新动作，再取消在途、注销、关闭连接、释放端口和定时器。协议时钟与 UI/宿主时间分开。
7. 查询在接受、SIP 完成、业务聚合、取消/超时状态间转换。Catalog 固定结果快照后分批，SN 一致、总数一致；丢批、重复批、超预算和多来源不能伪造完整成功。对超 MTU 请求显式 TCP 选择/诊断，不静默截断。

## 4. 双标准与基础调研后续

GB35114-2017 的有日期引用 GB28181-2016 不自动替换成 2022；普通业务切片与 A/B/C 安全剖面单列。继续沿用标准入口已登记的 C.4 摘要/Date/Note、身份分隔符、keyversion、SVAC/GB/T 25724、证书服务与真实介质缺口。本轮未重新审核 GB35114 原文，不宣称关闭 LAB-G-02/03/06。

Agent A 在 M0 调研记录中建立角色（设备/平台/用户/密码提供器）、能力叶节点、引用资料、实现阶段和未决依据的表，承接 LAB-S-001—018 与 LAB-E/X；软件接口占位不能标“安全支持”。M0 只有基础研究与隔离接口，安全行为与独立向量按 M1—M5 继续。

## 5. M0 补审落点

协议资产 protocol-assets/m0-contract.json（gb2022-m0-2）记录扩展审核页与产品预算；m0-vectors.json 为独立 Python 字节/摘要 fixture。2022 附录 J(c) 明确查询设备包含自身及子设备，因此零通道 NVR 仍有自身项；空 Catalog 用合法时间过滤产生。

2022 标准模式按 4.3.2、9.1 引用 RFC3261 10.2，REGISTER Request-URI 使用无 userinfo 的路由主机/端口；6.1.2 的 From/To 身份域与路由地址分开。2016 规范性 J.1/J.3 确实示范带服务器编码的注册/注销 URI，2022 前言删除了该旧附录，不能把它直接视为 2022 当前条款。该形式作为 COMPAT-001 显式保留；两版 6.10 的编码差异由 COMPAT-002 限定处理，响应仍为 GB18030。原文事实、推导边界和已审页见兼容文档，不宣称 2022 原文另有一句直接禁止服务器编码。

补审范围仍不是全标准字段审核。全部 LAB-S/E/X 后续能力、引用与缺少依据见[叶节点清单](capability-leaves.json)。
