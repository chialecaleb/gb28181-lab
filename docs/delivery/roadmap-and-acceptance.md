# 交付路线与验收规则

范围与阶段技术门槛沿用[需求第 9、10 节](../requirements.md)，不在此复制数值或另定产品路线。[当前状态](status.md)记录实际实现。

当前完成仓库和文档治理。下一轮先制定完整工程计划，核对原有阶段门槛与标准依据，再建立 Go 核心、宿主和测试入口。基本功能贯通后持续反馈迭代，完整交付仍覆盖原需求的适用范围。

## 验收映射格式

每个进入实施范围的需求记录：需求 ID、标准条款/产品依据、设计位置、测试 ID、前提、操作、预期、失败边界、实现位置、执行版本、证据和状态。一项需求可对应多个用例，缺项不能留空后宣称覆盖。

用例定义与执行结果分开：计划可写预期；证据用 passed、failed、not-run、blocked。已有 LAB 编号保持稳定。当前未建立产品执行矩阵，不声称已经完成全标准追踪。

## 退出条件

工程交付需要实现存在、相关自动门禁通过、文档一致、必要审查和无未处理核心缺陷。真实设备互通、容量、真实密码产品及用户体验分别验收，缺环境不得用自模拟或静态检查替代。人工检查保持在 USER-ACTIONS，不阻断无依赖工程推进。
