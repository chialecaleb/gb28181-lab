# M0 当前计划：工程基础与四项信令

初始日期：2026-10-07；集成更新：2026-10-13。需求正本为 [requirements](../requirements.md)，架构正本为 [design](../design.md)。本页是 M0 唯一实施计划。本轮已按用户确认补齐两种模式和 UDP/TCP 兼容外测，M0 当前范围完成；第 7 节保留首次实施历史，第 9 节记录本轮范围、标准解释与收尾，第 10 节记录用户新授权的历史整理与集成。

## 1. 目标与范围

按用户最新要求，将原 M0 的基础调研扩展为可运行的最小产品切片：核对技术栈、双标准角色与差异、建立 Go / React / Windows 桌面及 Linux Web 基础框架，实现 REGISTER、Keepalive、DeviceInfo、Catalog，并让用户在工作台观察真实信令与状态。M1—M5 的媒体、安全和完整产品承诺保留。

M0 以一个合成设备、一个通道、一个内置平台为默认演示；独立夹具覆盖零通道、多通道和边界。设备可以切换绑定到外部测试平台。内置平台和设备必须经实际回环 SIP 通信；应用服务直接返回模拟成功不算实现。基础传输覆盖 UDP、TCP；外部对端实测按其实际支持分项记录。

| 交付项 | M0 必须具备 | 本阶段边界 |
| --- | --- | --- |
| 工程 | Go 模块及锁定依赖、React/TS/Vite、薄 Wails 宿主、独立 HTTP 宿主、CLI 测试入口、统一服务层 | 不实现全部 MCP 工具；MCP 完成规范/SDK 调研与适配边界 |
| 配置/存储 | 本地配置优先级、凭据隔离、监听/目标分离、单实例所有权、SQLite 最小配置迁移与重启恢复 | MySQL/PostgreSQL 只保留接口和后续验收项；在途 SIP 不恢复为有效 |
| 注册 | 内置 registrar、设备 UAC、Digest 挑战、刷新、注销、失败/过期/重试、TCP 断链恢复 | 重定向完整流程留 M1；收到 3xx 明确不支持且不得继续显示注册成功 |
| 心跳 | 设备 MESSAGE Notify、平台确认与双向离线判断、重注册后恢复 | 子设备故障完整建模留后续；空 Info 与字段规则按原文处理 |

| 目录 | 查询、零/单/多通道、Num/SumNum、一致 SN、串行分批/确认、取消与超时 | 订阅/通知、跨域/级联目录留后续；不能把普通分页 API 当协议分批 |
| 工作台 | 实验空间/设备树/绑定选择、四动作、状态摘要、报文/时序/结构解析/十六进制、分层验证与证据导出 | 媒体、PTZ、安全等入口清楚显示未实现；无模拟视频或伪造通过状态 |
| 测试 | 独立向量、故障与清理、同一服务跨入口测试、真实界面操作、受控外部互通 | 不声明全标准符合性、容量或 GB35114 安全通过 |

## 5. 应用契约与默认资源策略

统一应用层最少提供设备/绑定读写、启停/注册/注销、心跳观察、DeviceInfo/Catalog 查询、操作状态、trace 查询和证据导出。每次操作生成 operationId，固定配置版本及目标；查询关联 bindingId + CmdType + SN + 目标身份，SIP 事务仍用 branch/CSeq/Call-ID 等协议键，不能混为一层。

HTTP 使用版本化 JSON DTO、结构化错误、输入大小/枚举校验、幂等与截止时间；桌面与 CLI 调用相同服务。M0 本地宿主仅监听回环，拒绝不可信 Origin/Host、跨源写请求和非本地访问，不开放匿名网络管理；选择本机令牌或受保护宿主会话并写入模块设计。Vite 仅接收公开配置，TEST_* 与任何凭据不能进入 bundle、API 配置回显或日志。

单设备演示上限与时间是产品测试策略，不是标准限值。M0 建议上限：活动实验 1、设备 1、通道配置最多 32、在途操作 16、trace 1000 条且总字节上限 8 MiB；超过明确拒绝或显示淘汰缺口。独立 Catalog 大批测试在隔离夹具中覆盖标准分批边界，不突破真实平台测试预算。标准注册/心跳定时保持原值；单元测试注入可控时钟，不修改宿主时间或外部平台配置。

## 6. 验证、风险与退出条件

| 验收组 | 必须验证 | 结论范围 |
| --- | --- | --- |
| 配置 | 环境变量优先级、空值、引号/中文路径、端口冲突、秘密不回显、TEST_* 隔离 | 准备工具与 Go 加载器分别验证，结果见实施证据 |

| 协议 | [用例矩阵](m0-protocol.md)全部 M0 项、独立字节向量、错误与超时 | 内部互测、独立向量、外部平台分别报告 |
| 资源 | 注销、超时、取消、端口占用、关闭/重启、晚到报文无旧代次副作用 | 事务、定时器、连接、操作、trace 均有界 |
| UI | 真实操作、分层结果、原始字节、错误可见、截图/键盘、敏感信息隐藏 | 主观验收状态单列，不因图上有“通过”就填通过 |
| 外部测试 | SIP 参数发现、请求/响应/业务/平台观察、注销、只清理自己资源 | LiveGBS 不具备某能力时记录差异，不能修改标准实现迎合对端 |

风险与处理：sipgo 的字节保真/事务策略先用最小验证约束；Wails/Node/Go 组合在锁定前实测；SQLite 只存关键配置，不逐心跳写盘；GB18030 与 XML 声明以最终字节向量验证；安全与媒体尚未实现时在能力表/UI 中明确禁用。第三方登录或 SIP 参数未知仅暂停 P6，不暂停框架与独立信令开发。跨域重定向、媒体、GB35114、完整账号系统和容量均不纳入 M0 通过数量。

M0 完成要求 P0—P7 的范围内代码真实存在、检查与自审通过、文档一致、启动入口可复现、缺项清楚；外部环境受阻时只能交付“内部切片完成、外部互通受阻”，不能宣布完整退出通过。原 M0 的双标准全功能叶节点调研继续保留，Agent A 至少明确每一需求组的后续阶段与缺少依据，不能删减原承诺。

回退通过本仓库任务分支/可恢复提交进行；停止应用、释放本次端口和设备、保留本地凭据与证据。数据库迁移前备份；不使用 git clean、不删除用户样本、不回滚外部平台全局配置。
