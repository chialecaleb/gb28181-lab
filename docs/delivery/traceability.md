# 需求到证据追踪

需求正本为[requirements.md](../requirements.md)，设计中的最后一节已有功能组对应。这里规定实施记录格式，不复制全部需求或声称完整逐条覆盖。

| 切片 | 需求入口 | 设计入口 | 当前状态 |
| --- | --- | --- | --- |
| 工程与宿主/接入边界 | LAB-R | 技术决策、模块边界 | 未实现 |
| 注册、心跳与目录 | LAB-C、LAB-F | SIP/GB 状态机、传输、查询 | 未实现 |
| 实时、历史与媒体 | LAB-F | 媒体、会话、录像 | 未实现 |
| 国密与安全角色 | LAB-S | 证书、密钥、信令、安全媒体 | 未实现 |
| 产品工作流 | LAB-E、LAB-X | UI、权限、观测、自动化 | 未实现 |

每个进入实现的具体需求建立一行记录：需求 ID、标准版本/条款/角色/方向、设计位置、代码位置、用例 ID、输入与失败边界、预期、执行版本、证据路径、状态。证据状态为 passed/failed/not-run/blocked；一条需求可对应多个场景。

现阶段只建立追踪结构，尚无真实产品测试记录。首次实现先选择端到端垂直切片，而非为全部目标填假代码或假通过。双方互通报告不替代本仓库单元、独立协议向量与第三方对端验证。
