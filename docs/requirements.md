## 1. 产品定位与约束

GB28181 Lab 将协议条款转成可配置、可操作、可观察、可验证的虚拟设备行为，用于协议学习、第三方平台联调、自动化场景和容量测试。它不仅回复报文，还要模拟主动注册、报警、订阅通知、会话建立与关闭以及真实视音频效果。

| 编号 | 硬性要求 |
| --- | --- |
| LAB-R-001 | 设备和应用核心采用 Go，前端采用 React + TypeScript，Windows 桌面使用 Wails。 |
| LAB-R-002 | Windows 发布包可安装或解压后双击启动；Linux 提供无 GUI 的 Web 部署，复用相同应用规则与协议核心。 |
| LAB-R-003 | 软件具有自己的配置、存储、用户权限、媒体、条款库、场景和发布包；不依赖任何指定平台软件或其他产品仓库。 |
| LAB-R-004 | 虚拟设备 / 平台可直接接入符合目标标准的第三方平台；内置平台也能接收真实或虚拟设备、下级平台并向上级联。第三方无需适配模拟器管理 API、私有消息或厂商编码。 |
| LAB-R-005 | 完整实现 GB/T 28181-2022 与 GB 35114-2017 全部适用功能，包括 A / B / C 级前端、用户终端、安全平台与级联；阶段版本公开缺项，不以 XML 回复、固定密钥或假验签冒充完整实现。 |
| LAB-R-006 | 必须支持 10,000 个独立 SIP UA 在线的容量目标，以及预览 / 回放合计 100 路同时推流目标；硬件和媒体剖面另行锁定。 |
| LAB-R-007 | 低资源占用是核心约束：空闲逻辑设备不持有独占进程、线程、编码器或无界缓存。 |
| LAB-R-008 | 全景图片 / 视频、时间戳、独立 PTZ 与实际推流结果一致；页面中的运动不能代替码流里的运动。 |
| LAB-R-009 | 所有可查询基础信息和允许配置的协议参数可编辑、批量生成、回读与导出。 |
| LAB-R-010 | 提供内置虚拟平台驱动的自操作页面、原文入口、自定义报文测试和 MCP 服务。 |

“无私有协议”适用于第三方 GB 互通；桌面绑定、管理 REST、MCP、媒体工作进程通信和浏览器播放接口可由产品自行设计。标准定义的 X-GB-Ver 等字段照常实现。非 SIP 私有协议转换网关不是本软件角色；GB 边界可与合规网关互通。

## 2. 角色、模式与计数

### 2.1 模拟角色

| 角色 | 行为范围 |
| --- | --- |
| IPC / 摄像机 | 单通道音视频、云台、配置、录像、报警、抓拍、升级 |
| NVR / 多通道设备 | 一个独立注册身份及多个通道，目录、子设备状态、录像与媒体分别关联 |
| 报警 / 探测设备 | 报警、布撤防、复位、订阅与事件 |
| 音频设备 | 广播接收、语音对讲、方向协商和音频状态 |
| 移动设备 | 位置、轨迹、移动通知及订阅 |
| 扩展设备 | A.4 的停车、车辆抓拍、道闸、门禁、人员 / 凭证、安检与检测事件 |
| 平台场景节点 | 上级 / 下级平台、同级互联、目录级联、多路径和第三方呼叫控制 |
| 安全功能实体 | A / B / C 级前端、安全用户终端、中心信令控制服务器、信令安全路由网关、安全媒体服务器；证书 / 视频密钥服务测试实体及外部合规服务对接 |

内置平台同时承担自操作、媒体验证和真实第三方接入；平台场景节点覆盖完整平台角色，可作为上级接入下级并向上注册。不得把门禁、级联、对讲等不适用行为硬塞进普通 IPC 角色，也不得把内置平台长期限定为 REGISTER / PTZ 辅助端而删除平台完整目标。

### 2.2 工作模式

| 模式 | 设备目标与操作路径 | 要求 |
| --- | --- | --- |
| 外部接入 | 虚拟设备 → 第三方平台 | 内置平台可停用；接入、媒体和配置不依赖本地实验平台 |
| 自操作实验 | 虚拟设备 → 内置平台；UI → 平台 → 真实 SIP → 设备 | 设备经过相同解析、校验和状态机；平台接收真实媒体 |
| 场景 / 压测 | 场景调度 → 设备组、平台节点、故障动作 | 固定配置版本、随机种子、时钟参数和证据策略 |

默认以不同设备组 / 配置快照隔离外部接入与本地实验。切换同一设备的目标平台须处理会话停止、注销和重新注册，不静默夺走原有连接。多平台绑定作为显式能力：每个平台的鉴权、注册、订阅、对话、媒体会话隔离；同一设备的物理 PTZ / 录像状态共享，控制按单一设备事件序列执行。

10,000 设备表示 10,000 个独立 UA，不表示一个 NVR 下的 10,000 通道。通道数、绑定数、SIP 连接数、媒体会话数、源解码任务数、独立编码任务数、浏览器观看数分别计数。100 路指预览与回放合计并发，必须覆盖 100+0、0+100、50+50；下载和音频另设业务剖面，不偷换为额外免费容量。

## 3. 标准基线与完整行为

### 3.1 通用符合性

| 编号 | 要求 |

### 3.3 编解码与完整交付边界

首个媒体闭环使用 H.264 + G.711，完整能力清单必须分别列视频 H.264、H.265、MPEG-4、SVAC 和音频 G.711、G.723.1、G.729、SVAC、AAC，G.722.1 列为可选扩展。编码可选与解码要求不能混为一谈：附录 F.1 对接收 / 解码角色要求视频四种、音频五种同时支持。内置平台的完整接收验证能力也受此约束，不能只转发而宣称能解码。

产品完整模拟目标纳入这些媒体类型的生成、协商与接收验证；每种编码的独立媒体资源和实现来源单列，百路容量首轮只针对规定的 H.264 剖面。缺少 SVAC 等实现时保持受阻条目并限制能力声明，不能用 H.264 字节伪标其他编码。

基础第 8 章与 GB35114 全部适用功能均必须完成。证书、TLS / IPSec、SM3、完整性及跨域身份按条款强度建模；不把算法库可调用、TLS 已开启或固定加密素材视作完整安全协议。A.4 与 GB35114 的引用规范必须补齐，不能由任意 JSON 或本地动作代替标准消息。

### 3.4 GB35114 完整安全能力

GB28181 Lab 必须实现设备端、平台端和安全用户终端的真实协议及密码运算，可直接与第三方互通。实验用证书 / 密钥服务及软件密码提供器用于功能研发；正式密码产品剖面必须接入符合第 5.1 条要求的产品和安全介质，分别发布证据。模拟角色不意味着可以返回固定签名、跳过验签或明文代替密文。

### 3.5 两标准组合与实现声明

- GB28181 的业务基线为 2022；显式兼容模式仅覆盖已登记的 COMPAT 项，不扩展通用 2011 / 2016 兼容承诺。GB35114 明确引用的 2016 条款必须保留并映射到所选业务版本，不能把引用年份机械替换为 2022。
- 普通配置与 GB35114 安全配置分别验证；同名头域、摘要、SDP、媒体封装按各自审核规则执行。第 8.6 条的专项安全要求进入安全配置，禁止自动降级。
- 设备多平台绑定的安全上下文、证书、密钥及授权独立。用户可以模拟能力不足或撤销，但实际协商失败必须可见；不能仅编辑“认证成功=true”让标准模式通过。
- H.264 / H.265 普通媒体支持与 GB/T 25724-2017 安全媒体格式分开验收；WebRTC、HTTPS 或软件加密不替代 GB35114。转码后的派生流保留源证据引用，不声称保留源设备对新字节的签名。
- 完整版本须通过 LAB-F、LAB-S、LAB-E、LAB-X 的全部适用验收；“软件功能已验证”“合规密码产品已验证”“第三方已互通”分别标识，任何未关闭项都不因称为模拟器而豁免。

| LAB-N-012 | 数据与恢复 | 三数据库等价功能及六个有向迁移组合通过；分别测批量提交、索引检索、备份与恢复。恢复后的新会话不复用挑战，新加密不复用旧 VEK / IV 组合；历史密文可按授权回放，已撤销信任保持失效 |

100 × 4 Mbit/s 为 400 Mbit/s 媒体有效载荷；封装、音频、收流、浏览器分发与双向网卡另计。100 路 1080p / 25 fps 约为 51.84 亿像素 / s，仅一次 YUV420 帧流动约 7.78 GB/s；不能用信令主机规格推断它也能承担该媒体目标。

每设备 16—64 KiB 的应用状态预算意味着 10,000 设备约 156—625 MiB，此数字不包含 Go 运行时、数据库、内核连接、日志和媒体，不是进程实测值。报告同时记录 Go heap、RSS、媒体原生内存、WebView / 浏览器、GPU / 显存与内核资源。

第 5.3 条的端到端信息延迟上限直接接入监控中心为 2 s、到用户终端为 4 s；按标准场景独立测量，不由 p95 体验目标替代。网络质量条件与同步误差随报告保存。

默认提供“教学追踪”和“容量运行”配置：前者对选中设备保留全字节，后者采用指标、有限环形缓冲、抽样和异常保留。界面始终显示当前记录覆盖率和缺口；压测不能全量推送 10,000 台设备的所有报文到前端。
