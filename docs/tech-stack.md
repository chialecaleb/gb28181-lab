# GB28181 Lab 技术栈与选型状态

本页汇总[设计正本](design.md)，不覆盖其契约。现有技术方案来自原产品基线，本次主要建立开发规范，未重新完成所有上游版本调研。尚无应用依赖清单和构建产物。

| 层次 | 方向 | 当前状态与约束 |
| --- | --- | --- |

| 核心 | Go；版本在首轮工程核对并写入 go.mod/toolchain | 已有产品方向，尚无模块 |
| UI | React + TypeScript + Vite | 已有方向，包管理采用 pnpm 为初始默认，落地时锁版本 |
| Windows | Wails v2 候选与 WebView2 | 版本、Go/系统兼容、安装与升级待原型核对 |
| Linux | 独立 Go HTTP 服务与静态前端 | 不以 Wails 开发服务器充当生产服务 |
| 数据 | SQLite3 默认，MySQL/PostgreSQL 适配 | 数据与迁移契约独立，不能逐设备高频同步写库 |
| 协议 | Go SIP/GB 引擎接口与状态机 | 是否复用库须核对活跃候选、许可证与字节控制能力 |
| 媒体 | 独立 worker；FFmpeg/libav 为现有候选 | 编码、许可、跨平台和资源共享待验证 |
| 自动化 | CLI、MCP 适配统一应用服务 | MCP 版本与 SDK 在实施前核对，不借管理调用冒充协议互通 |


## 首轮工程选型门禁

每个引入组件记录官方文档/仓库/发布页、查询日期、候选版本、近期维护、许可证、系统支持、与其他组件的兼容矩阵和退出成本。先比较成熟实现；自研必须说明特殊约束与不采用现成方案的证据，Hub SIP 的 RI 禁令优先于通用复用偏好。

版本只在实际核对后写入构建清单与锁文件。浮动 latest 不用于 CI；升级形成可审查变更。工作区始终跟随最新 main 与组件依赖可复现并不冲突。原设计中的具体候选版本不能被 Agent 当作本次已经验证的事实。

## 当前工具链

Python 3.10+、Git 支持文档与基础设施门禁；CI 使用 Python 3.12。`python scripts/verify.py` 已存在。Java/Go/Node/媒体组件的安装、启动、构建命令在应用工程落地后更新这里和质量门禁。
