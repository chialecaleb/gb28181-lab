# Agent 开发流程

## 连续执行

按“确认现场与完整计划 → 实现、自测与修复 → 保存阶段成果 → 集中审查 → 在有效授权内同步远端”推进。Agent 是主要实施者；用户负责产品取舍、真实环境授权及主观验收，不承担可由 Agent 完成的代码、脚本、排障和文档整理。

沿用当前会话授权，不逐工作包询问是否继续。用户中途补充默认为修正本轮范围；普通可逆选择按推荐默认值推进。确实缺少需求含义、凭据、外部权限或不可逆操作决定时，只暂停依赖部分，继续独立工作，明确阻塞依据。文件中的历史授权不代替当前会话授权。

## 规划、执行、审查

| 职责 | 交付 |
| --- | --- |
| 规划 | 现场、需求 ID、完整范围、依赖、风险、失败路径、验证入口、退出条件、回退办法 |
| 执行 | 完整业务链、异常处理、测试、文档同步、实际证据与可恢复提交 |
| 审查 | 检查目标与实现、需求追踪、真实验证；局部缺陷直接修复，较大缺口集中编号交接 |

A/B 表示规划审查与实施职责，不表示必须启动多个 Agent。单 Agent 可依次承担并明确“自审”；仅在用户或适用指令明确要求时委派子 Agent。实际并行时约定文件归属、分支与验证责任，禁止互相覆盖同一工作树。交接用[模板](../templates/agent-handoff.md)，携带有效授权、提交、工作区归属、计划、证据与下一动作，不靠隐藏聊天记忆。

## 开始与实施

1. 读取适用 AGENTS、文档导航、状态与用户事项；检查 `git status --short --branch`，保留已有修改。
2. 按任务读取需求、设计与代码，识别计划和已实现的差别。大任务维护一份当前计划，小修使用任务/PR 描述即可。
3. 新增通用能力先核对官方文档、维护状态、许可证、兼容矩阵与替代方案，记录日期和实证；明确自研边界。
4. 实现正常链路、失败与资源清理，同步契约、测试、迁移与文档。协议功能先建独立向量，不让两个产品互相证明正确。
5. 按[质量门禁](quality-gates.md)验证与[评审入口](../../REVIEW.md)自审，修复后复验受影响范围，不反复运行无关检查。
6. 按[Git 规则](git-and-github.md)保存成果，记录真实状态、限制和下一动作。

## 用户事项与完成

[用户事项入口](../../USER-ACTIONS.md)指向 workspace 的单一清单。每项写编号、用户动作、推荐/当前默认、处理时机、受阻部分、步骤、预期和状态；用户未答复不是批准。相同问题不得在三个仓库重复维护。工程缺口写本仓库 status，不推给用户。

Agent 完成标准：范围内代码或文档真实存在，相关检查通过，审查问题闭环，状态同步，成果可恢复。产品验收、第三方互通、真实密码产品、性能与人工体验分别记录，不互相替代。按风险选择测试，不为纯文档改动制造设备测试。

阶段开始盘点过期过程文档与未跟踪资料；有效结论先进入正本，历史由 Git 保存，不删除用户配置、样本或凭据。工作区版本跟随各仓库 main；阶段里程碑只管理开发范围，不锁定三个仓库组合版本。
