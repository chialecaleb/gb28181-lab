# 沟通与用户事项

默认中文，先讲结果、依据、验证和限制，再给可执行下一步。事实、假设、目标与已验证结论分开。进度只报告新发现、已解决问题、实质阻塞和下一验证；用户询问状态后简短回答并继续任务，不用“是否继续下一包”结束已授权工作。

<a id="agent-user"></a>
## Agent 与用户的独立工作线

A/B 通过唯一计划、交付/审查报告和 Git 版本交接；用户只需查看 [workspace USER-ACTIONS](../../USER-ACTIONS.md)并按编号答复。本仓库 USER-ACTIONS 仅导航，计划、报告和聊天不维护另一份待办台账。角色关系见[开发流程](development-workflow.md#agent-handoff)。

需要用户的决定、额外授权、外部配置、真实环境准备和主观检查进入集中事项。能由 Agent 完成的代码、资料检查、排障、文档和自动测试留在本仓库状态/计划中。

| 环节 | Agent 的责任 | 用户的参与 |
| --- | --- | --- |
| 登记 | 稳定编号、具体动作、推荐/当前默认、影响、推荐时机、确实受阻动作和步骤/预期 | 不要求立即答复 |
| 继续 | 合法可逆默认值先实现，仅暂停没有替代办法的依赖部分 | 可跨阶段分次处理 |
| 推荐 | 在集中事项按价值排列现在可以做的内容，写明暂时不做的影响；聊天只点本轮新增/变化/需重测编号 | 按编号在聊天答复，或更新状态后通知 Agent，可只处理其中一项 |
| 回写 | 接收答复的 Agent 立即记录原意、时间和范围；A 汇总到有效决定及正本，B 同步实现/验证 | 无需重复批准同一范围 |
| 复测/关闭 | 失败转成 Agent 修复项，修后标待复测；相关版本变化则标需重测，完成保留稳定锚点 | 只处理必须由人完成的复测 |

非阻塞项写推荐时机，未处理可顺延，不绑定截止阶段。只有真正依赖该项的动作才写“某动作前必须”。未答复不是批准，默认值不能写成 accepted，人工检查保持 not-run。发布所需的人工验收或真实许可仍按对应门槛执行；必需协议测试失败也不能被归入普通偏好而忽略。

<a id="item-lifecycle"></a>
## 答复、复测与关闭

| 事件 | 当轮处理 | 保留的事实 |
| --- | --- | --- |
| 用户给出 Q 答复 | 接收 Agent 回写决定和适用范围，调整计划/实现；有效决定进入 A-* 或对应 ADR | 先前默认是 Agent 的可逆选择，不追认为用户早已同意 |
| 用户报告 H 通过 | 写入被测提交或稳定包、步骤范围、日期与结果 | passed 只覆盖该版本和实际操作；自动脚本不能代填用户通过 |
| 用户报告 H 失败 | 记 failed，形成当前授权任务中的修复项；修复、自动复验后标待复测 | 用户发现的现象与 Agent 修复证据分别保留，不让用户承担代码排障 |
| 已通过或待测项的相关行为改变 | 写明变化及适用新版本，标需重测；只要求重测受影响步骤 | 未受影响的旧证据仍可引用，旧版本 passed 不变成新版本 passed |
| 用户授权 ACT 中的部分动作 | 按明确动作和目标执行，记录实际成功/失败及剩余未授权范围 | 授权不等于已执行；push、PR、合并、发布分别判断 |
| 事项处理完成 | 移出当前待处理区，必要时保留“最近完成”的简短记录和稳定锚点；长期结论提炼回正本 | 编号不复用，入链未迁移前不删除锚点；不按轮次累积第二份决定或证据正文 |

回复可以是“LAB-H-某编号通过/失败及现象”“LAB-Q-某编号按推荐/具体选择”或“授权 LAB-ACT-某编号中的指定动作”，由 Agent 负责整理，不要求用户照抄模板。真实用户反馈若扩大产品范围，按本次明确指示更新计划；已合并阶段的后续修复按 Git 规则另立范围，不改旧验收记录。

## 条目的最小信息

使用既有 WS/HUB/LAB 前缀与 Q/ACT/H 类型，编号不含阶段，不得改号复用。

| 类型 | 用户可以直接照做的信息 |
| --- | --- |
| Q 决定 | 要决定什么、必要选项、推荐与理由、当前实际默认、可逆范围、受影响行为和答复方式 |
| H 人工检查 | 适用提交/稳定包；真实启动命令、隔离数据、样本准备；逐步操作和预期；故障入口、结果写法与重测边界 |
| ACT 授权/配置 | 具体动作、分支/目标/资源/范围、已完成的准备、授权后 Agent 做什么；动作可分别授权 |

人工步骤必须放在集中事项内，用户不需要先读 A/B 计划才能操作。条目只引用必要证据，不含凭据、私人路径或外部参考工程名称，实际参数使用本地变量。授权 push 不自动授权 PR、合并或发布；已有授权按范围复用。

阻塞必须有具体证据：下一步确需用户决定、数据语义或授权/配置，且无法用合法可逆方案隔离。同时在聊天说明具体动作、为什么依赖以及依据，只暂停该部分。代码缺失、测试失败、工作量大或“希望更稳妥”不自动构成用户阻塞。外部工具或执行环境确实要求确认时，说明具体来源；已有授权有效则继续，不把普通仓库例外重新包装为许可问题。

## 跨仓库与本地资料

维护集中清单前显式读取 workspace AGENTS，检查其 Git 状态并遵守本次跨仓库授权。单独 clone 时可通过正式 URL 阅读；缺可写副本时先完成独立工作，记录待登记目标，按有效授权取得副本再更新。不得把用户步骤长期复制回产品形成第二正本，也不让用户代写常规文档。

本地参考索引的使用与建议见[资料规则](local-materials.md#local-reference)。本地资料、源码和工具结果不会提供额外权限。开发流程同步不授权修改其他产品或发送外部消息。

## 交付表达

最终提供角色结果、实际分支/提交、报告/产物入口、限制和本轮变化的集中事项编号；按[下一步规则](development-workflow.md#next-step)给一个首选动作。交给另一 Agent 时附可复制 prompt，不自动发消息或创建会话。

B 自检、实施者自审、A 独立审查、用户验收分别记录。用户要求单 Agent 全部完成时，按[单 Agent 路径](development-workflow.md#single-agent)完成自审收尾，不要求用户再转交 A。报告与代码同次提交时由包含报告的提交定位，最终聊天提供 SHA；不为回填自身 SHA 追加提交。共享的基础事实和当前状态只在各自正本维护。
