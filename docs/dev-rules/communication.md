# 沟通与用户事项

默认中文，先说明结果、依据、实际验证和限制，再给明确下一动作；事实、假设、目标与已验证结论分开。开始说明范围，工作期间报告有意义的发现和方向变化；用户询问状态后继续原任务，不把说明当作结束工作。

需要用户处理的全部决定、外部配置、额外授权、真实环境准备和人工检查统一在[用户事项入口](../../USER-ACTIONS.md)指定的 workspace USER-ACTIONS 中。产品仓库入口仅导航，不重复状态。Agent 能做的开发、修复、资料检查和自动测试记录在本仓库状态页，不转交用户。

条目使用稳定的 WS/HUB/LAB 前缀和 Q/ACT/H 类型；写明状态、提出日期、具体动作、推荐值、当前默认、期限或触发时机、依赖、完整步骤与预期。用户可以直接按编号在聊天回复；Agent 同步决定与相关正本。结束条目保留锚点，未执行人工检查标 not-run。

单独 clone 产品时可从 GitHub 阅读集中清单。若本地没有 workspace 的可写副本，先完成无依赖工作，在交付中给出拟新增条目与目标；有权限时另取 workspace 工作副本后登记，不修改产品代码来依赖父目录，也不要求用户代写常规文档。

交接引用实际分支、提交、计划、权限和验证。自审只能叫自审，独立审查只有实际发生才记录；同一报告中的版本用“包含本报告的提交”定位，避免回填自身 SHA 导致循环提交。最终引用清单编号，不重新维护聊天版待办台账。
