# GB 协议工程规范

适用于 GB/T 28181-2022、GB 35114-2017、其适用引用规范，以及产品 HTTP/MCP 契约；业务需求和设计仍由各自正本维护。

## 从条款到实现

每条实现规则保存标准号/版本、条款、印刷页与 PDF 页、角色、收发方向、应/宜/可、前置条件、产品需求 ID、差异决定、实现位置和独立验证。条款表可以逐功能建立，不提前把整个标准标为已覆盖。

原始 PDF 为核对依据，OCR 与示例报文只辅助检索；发现字段、摘要公式、分隔符或编码差异时回到原页，写明解释与未决状态。GB35114 有日期的引用不自动替换为新版。未取得引用标准的部分标“缺少依据”，不能把未实现改成不适用。

## 报文与状态机

逐项定义字节编码、序列化、长度、转义、大小写、可选字段、未知字段、顺序与边界。认证、签名所用原始字节和用于展示的解码结果分开，禁止格式化 XML 或改换行后再验签。敏感原文保留在受控本地证据中。

SIP 事务与对话状态分别建模；覆盖 UDP 重传、重复/乱序、迟到响应、序号、超时、注销及资源清理。TCP 覆盖半包、粘包、空包、连接失败和主动/被动角色。产品默认重试和限额不能伪称标准规定。

测试时间可控；每个场景说明拓扑、角色、网络、时钟、输入报文、预期转换、最终资源数量和清理时间。故障注入应隔离并明确标记，不能污染正常运行默认值。

## 媒体与安全证据

发出 SIP/XML 成功不等于媒体成功；真实验证 RTP/RTCP、封装、接收解码、时间戳、音画与 PTZ 效果。内置自操作、外部互通、容量与长期稳定性各自有证据，不互相替代。

密码验证至少覆盖有效、篡改、过期、吊销、不可信、错误身份、重放和密钥轮换失败，采用独立向量或独立实现比对。软件实验与真实密码产品剖面分开；固定密钥、假签名、跳过校验不满足安全验收。

协议实验报告使用[验证模板](../templates/validation-report.md)，原始抓包默认本地保存；公开报告记录脱敏方法与哈希对应，不能重写历史结果。真实设备和容量目标尚未验证时明确 not-run。
