# 质量门禁

## 当前已经可运行

前置：Python 3.10+、Git，仅 Python 标准库。在仓库根运行：

```powershell
python scripts/verify.py
```

统一入口执行文档登记/本地链接/锚点检查、工具回归测试、Python 语法检查、工作区与暂存区空白检查。workspace 另外检查共享标准的完整清单和 SHA-256。新文件先按路径暂存，检查范围是 Git 跟踪文件，不扫描被忽略的私人资料。`python scripts/check_docs.py` 可单独运行文档检查。

CI 使用相同入口，固定 job 名 repository-quality，只读执行。必须检查对应提交的实际运行结果，工作流文件存在不代表已成功运行。结构门禁不验证外部链接可达、协议语义、完整秘密识别或应用正确性。

M0 本地环境准备已有 `python scripts/local_env.py`（配置检查）与可选 `--probe`（回环 TCP connect 和临时 bind），详见[环境说明](local-test-environment.md)。其合成配置回归 test_local_env.py 已纳入上述 unittest 发现流程；CI 不加载个人 .env.local，也不探测个人平台。准备门禁不代表 M0 协议通过。

## 应用建立后按变更触发

| 变更 | 必要验证 |
| --- | --- |
| Go/Java 核心 | 编译、静态检查、真实单元/集成用例；适用的竞态或并发检查 |
| Vue/React | 锁文件安装、类型检查、构建、关键组件与端到端交互 |
| SIP/XML/SDP | 正常报文、字节编码、长度、未知字段、半包粘包、重传乱序、超时清理、独立向量 |
| 媒体 | 实际接收/解码、音画、时间戳、TCP/UDP 角色、结束资源回收 |
| 安全 | 独立密码向量、篡改、重放、吊销、越权、轮换与异常清理 |
| MQ/集群 | 重复投递、崩溃窗口、所有权代次、网络分区、恢复及有界积压 |
| 数据 | 三数据库适用剖面、迁移失败恢复、备份还原与权限 |
| 性能 | 提交 SHA、硬件、时长、设备/通道/媒体分别计数、内存/CPU/句柄/丢包及清理 |
| UI/发布 | 空/错/忙/取消状态、键盘/输入法、安装升级与真实截图 |

M0 已建立应用工程，实际门禁如下；媒体/安全等尚未实现的项目仍只在对应变更时运行。纯文档不要求实机测试；工具改变需要回归正反例；测试失败先修复，不削弱断言制造通过。

## 交付检查

阅读最终差异、确认无凭据/真实抓包/绝对路径，核对需求—设计—用例—证据。报告生成后还要检查文件名、报告正文、工作树与暂存版本，避免工作树已清理而暂存区仍含旧内容。准备推送时另外核对实际待推送提交；有限路径规则不等于完整秘密识别，二进制、图片和外部工程叙述仍需语义核对。审查范围和未测部分明确；独立产品验证、双方互通、第三方验证和密码产品验收分别记录。未决用户事项不会阻断无依赖的自动工作。

## A/B 的验证责任

A 规划给出整阶段必需用例、预期/失败边界和证据要求，区分已有命令与待建立检查。B 实施后完成自检、修复、源码/产物版本核对，再交可审查版本；A 对照同一计划核对真实实现与证据，补必要验证，局部修复后只复验受影响范围与新风险。证据复用要核对源码、依赖/锁文件、测试、样本、执行配置和环境假设；未受变化影响的有效记录可复用，换 Agent 或仅保存 commit 不会自动使它失效。

必需命令缺失要补实现或明确记录未运行，不能用 `--if-present`、删断言、改旧报告或放宽目标制造通过。检查基础设施变化要验证能检出反例；本次纯 Markdown 流程修订运行 `python scripts/verify.py` 和语义自审，不因此重跑无关应用、SIP、设备或容量测试。

B 自检通过不等于 A 已审，A 技术通过不等于用户验收。用户要求单 Agent 全部完成时，当前 Agent 按[评审入口](../../REVIEW.md)完成收尾自审与修复，报告写明“自审完成，独立 A 审查 not-run”；默认分工不另加独立审查前提。主观检查和非阻塞偏好可在集中事项顺延；阶段要求的自动证据、外部协议互通、安全与恢复仍按实际门槛判断。M0 的 REGISTER 400 不会因协作流程修订变成通过。远端 CI 只有对应提交实际运行后才能记录成功。

## 证据、失败与整理

环境失败、产品行为失败和未执行分别记录原因、影响与复测入口。先修复可由 Agent 解决的实现/工具问题，不把失败包装为用户人工检查，也不通过重复同一无变化检查代替诊断。产品取舍确实改变目标时，先有有效决定并同步正本，旧失败保持原结论。

文件整理遵循[治理规则](../governance/documentation-policy.md#stage-cleanup)：抽查合并依据、内容去向、稳定编号、入链和测试映射；未合并证据与用户资料保留。当前没有阶段标签或文档退役的自动门禁，这部分必须在报告中给出实际人工/Agent 核对结果。文档检查通过只支持结构结论，不能当作已经完成内容提炼。

## M0 应用门禁

运行 `python scripts/verify_app.py --e2e`：冻结 pnpm 安装、Vitest、TypeScript/Vite、Go 模块校验、单元/网络/存储/适配器测试、vet、宿主构建、Playwright 真实操作。首次 E2E 先执行 `pnpm --dir web exec playwright install chromium`。Linux 有 C 编译器时追加 `--race`；Windows 本轮未配置 C 编译器，race 在隔离 WSL 工具链执行，不能写成 Windows race 通过。

CI 保留 repository-quality，包含固定 SHA 的 Go/Node 设置及 `verify_app.py --race --e2e`，不读取 .env.local、不访问 LiveGBS。每次远端集成核对 PR 对应提交的实际检查结果，不用本地 passed 代替远端状态。Windows 桌面实际启动/关闭另行验证；操作截图、兼容互通、历史失败及自审见[实施证据](../evidence/m0-implementation.md)。

两种模式覆盖默认/旧配置、枚举拒绝、运行中锁定、历史模式不重标、内置绑定不启用兼容及 COMPAT-001/002 正反例。TCP 最终响应后立即断开必须保留已收到的 SIP 结果，无响应仍在截止时间内失败。外测工具的合成回归由 repository-quality 自动发现，真实 P6 从不由 CI 自动启用。

真实 P6 在会话已有授权内分别指定 UDP/TCP 与模式。判定同时检查 Go 应用退出状态、独立原始 SIP 字节/事务/业务关联、正常三周期、平台观察、注销与仅清理本次离线设备；任何一层失败都保留 failed。按[兼容文档](../compatibility.md)记录每次执行，显式兼容成功不关闭严格 2022 对端符合性。
