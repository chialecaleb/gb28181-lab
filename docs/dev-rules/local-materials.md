## 本地功能参考

A 规划与 B 实现一个功能前分别检查对应索引。显式配置 `GB28181_REFERENCE_ROOT` 时先在该资料根定位 `gb28181-lab` 的索引；否则从仓库根逐级向上寻找最近的 `reference/<仓库名>/`，按 README.md、INDEX.md、REFERENCE.md 的顺序选择。没有则如实记录并继续独立研究，不猜测其他工程是有效来源。

索引和参考项目只读，不自行修改、移动、更新或拉取。只按索引注明或当前用户明确指定的用途阅读；参考项目的凭据、历史授权、产品决定和验收结果不进入 Lab。索引缺失不阻断用户明确指定的只读文档核对；不能据此扩大到其他资料或源码。复用代码需另核对许可证及实际授权，不能把参考设计解释为允许复制实现。

材料明显过旧时先说明证据日期与不确定部分，需要用户更新才登记对应事项，不自行更新源项目。逐文件同步流程时，记录核对日期、内容摘要/哈希、阅读范围、适用规则、目标落点和不适用理由；源项目名、私人路径和完整对照表留在 Git 忽略的本地记录，公共报告只描述本项目规则及验证。

建议新增参考时，只有当前任务允许写入该本地建议区时，才在索引同目录 PROPOSALS.md 追加功能、建议、许可、用途及理由，不直接改正式索引；集中用户事项只写不含项目名/私人路径的提示。缺少相应跨目录授权时先保留建议并按沟通规则登记，不因本页自动扩大写入范围。用户采纳后再更新索引。

公共文档、提交和报告只写本产品依据、功能领域及结论，不写外部参考关系、项目名或私人路径。官方标准、实际依赖和必要许可声明仍按其正本保留。

## 文件位置

2026-10-07 用户指定：LiveGBS 只能用于测试阶段，不得用于开发参考。开发时不查其源码/API 文档；独立实现与合成验证后，测试所需接口可按本地 TEST_LIVEGBS_* 和 test-only 索引定位。原图仅为视觉/功能参考，图片里的条款、报文与成功状态不作标准或验收依据。配置合同见[本地测试环境](local-test-environment.md)。

| 内容 | 位置与 Git 处理 |
| --- | --- |
| 本机资料、草稿、迁移备份 | .local/，忽略 |
| 真实配置 | .env.local、secrets/，忽略 |
| 抓包、录像、日志、构建证据 | captures/、recordings/、artifacts/，默认忽略 |
| 合成用例、脱敏证据 | tests/ 或 docs/evidence/，审查后跟踪 |
| 标准原始文件 | workspace 集中维护与校验；产品副本在 .local/standards/ |

`.gitignore` 不保护已跟踪文件；单机额外规则可用 .git/info/exclude。不用 assume-unchanged 隐藏秘密。发现凭据泄漏先停止传播并处理撤销，不能只补忽略规则。

清理前检查 `git status --short --ignored`、`git ls-files` 与忽略原因；不打印真实配置内容。移动前核对来源/目标绝对路径和文件归属，重要原始资料校验哈希；不自动执行 git clean -fdx，不删除用户样本。
