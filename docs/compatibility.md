# 标准模式、兼容模式与执行记录

本页维护模式合同、已登记兼容项和全部实际兼容执行的索引。业务基线为 **GB/T 28181-2022**；2016 版只作为具体差异的对照依据，不自动切换整套协议版本。当前实现与阶段结论仍以[状态](delivery/status.md)和[M0 实施报告](evidence/m0-implementation.md)为准。

## 两种模式

| 项目 | 标准模式 standard | 兼容模式 compatibility |
| --- | --- | --- |
| 依据 | 2022 版特殊规定优先；未作特殊规定的内容依其 4.3.2 遵循引用协议 | 保留同一业务基线，仅对明确登记的项作适配 |
| 启用 | 新配置和旧配置缺少模式字段时的默认值 | 在“设备与绑定配置 → 协议模式”显式选择并保存 |
| REGISTER Request-URI | 无 userinfo，使用合法路由主机及端口 | 外部绑定启用 COMPAT-001；内置平台仍使用标准格式 |
| 入站 XML | GB18030 规则 | 外部绑定的 ASCII 基础查询可使用 COMPAT-002 的 GB2312 声明 |
| 失败行为 | 保留拒绝/超时，不自动转入兼容模式 | 仍验证认证、身份、事务、业务应答、资源清理和真实结果 |
| 标准判断 | 按具体条款分别判断，不以模式名称宣称全标准通过 | 实际互通成功不抹去 RFC 条款差异或对端版本缺失 |
| 历史与导出 | 每个操作、每条报文记录当时模式和配置版本 | 另记录实际使用的兼容项；切回标准模式不重写旧记录 |

模式属于 Config 的 protocolMode 字段，由统一应用服务校验。只接受 standard / compatibility；旧客户端或旧 schema-1 存储缺少字段时按 standard 处理，不改 SQLite 表结构。注册或操作尚未结束时拒绝保存模式变更；先注销、完成清理再修改。凭据仍独立保存在受保护的宿主配置中。

本阶段的兼容模式不是完整 2016 协议支持，也不自动修改 X-GB-Ver 为 2.0；实际支持和版本检查保持独立。后续兼容项必须先核对目标版本原文、增加稳定编号和独立回归，再纳入此表，不能静默增添失败回退。

## GB28181 两版原文核对

核对日期：2026-10-11。先检索两版 OCR，再复核决定结论的 PDF 原页。以下明确区分原文事实与本项目采用的解释。

| 对照点 | 原文事实 | 对本项目的含义 |
| --- | --- | --- |
| 2022 4.3.2，印刷 9—10 / PDF 16—17 | “如本文件对各项功能有特殊规定应遵循本文件，否则应遵循 IETF RFC 3261 等引用协议。” | 不能仅凭通用 RFC 否定 GB 的明确特殊规定 |
| 两版 6.1.2；2022 印刷 11 / PDF 18 | username@domain 的特殊编码明确针对 From、To 头域；2022 允许十位域号、扩展域名、IP:port 或域名 | 身份域、认证 realm、实际路由地址各司其职；不能把此段直接扩展成所有 Request-URI 都必须含 userinfo |
| 2016 9.1.2.1 与规范性附录 J.1.1/J.1.3，印刷 115 / PDF 120 | 正文指向 J.1；示范使用 Register sip: SIP服务器编码@目的域名或IP地址端口 SIP/2.0，认证 uri 也含服务器编码 | 这种注册格式有旧版国标规范性示范依据，不称为无标准来源的厂商私有格式 |
| 2016 规范性附录 J.3.1，印刷 117 / PDF 122 | 注销使用同类 URI，Expires=0 | 沿用旧版格式时必须同时覆盖注册、刷新和注销 |
| 2022 前言，印刷 VI / PDF 7 | 明确“删除了2016年版的附录G、附录H、附录I、附录J” | 2016 J.1/J.3 不能不加说明地作为 2022 的现行规范性附录 |
| 2022 9.1.1(a)(b)、9.1.2.1—2，印刷 16—17 / PDF 23—24 | 注册、注销采用 RFC3261 REGISTER；刷新也遵循 RFC3261；保留认证与挑战流程 | 在已核对的 2022 注册条款中未找到重新规定带 userinfo 的 Request-URI 的例外 |
| 2022 9.1.2.3(d)，印刷 18 / PDF 25，OCR 对照 | 重定向的 Contact 格式含 SIP 服务器编码和地址 | Contact 与 REGISTER 请求行的 Request-URI 是不同字段；不能互相替代规则 |
| RFC3261 10.2、25 | REGISTER Request-URI 的 userinfo 和 @ “MUST NOT be present”；URI host 有独立语法 | 按 2022 4.3.2 的引用规则，标准模式采用不带 userinfo 的合法路由 URI |
| 两版 6.10，OCR 对照 | 2016 “宜采用 GB 2312”；2022 “应采用 GB 18030” | 旧版声明的处理单独登记为 COMPAT-002，不将其混写成 2022 编码规则 |

**项目采用的解释**：2022 标准模式采用上述引用规则；2016 注册示范形式作为显式兼容项保留。这个结论不是声称 2022 原文另有一句直接写着“禁止服务器编码”，也不是完整标准符合性认证。若后续取得适用勘误或明确的新规范解释，复核本条、模式行为、向量与本页执行结果，不把旧失败追认为通过。

本轮 PDF 视觉复核为 2022 页 7、16—18、23—24，2016 页 120、122；其余所列项为 OCR 对照。RFC3261 已从[官方原文](https://www.rfc-editor.org/rfc/rfc3261#section-10.2)重新获取，与先前保存文本字节一致。

资料身份见[标准入口](standards/README.md)。2022 PDF SHA-256 为 727dfbd2d1094780d2044800de7c59743550088d871a717c7bb4d36f33710cc6；2016 PDF SHA-256 为 28573e3e6e1e1aeb7695442f1586868004496d7d807f2a01b0233235cac529af。资料只读，不作为应用运行依赖。

## COMPAT-001：沿用 2016 注册请求地址

| 项目 | 合同 |
| --- | --- |
| 状态与授权 | 用户于 2026-10-11 明确选择显式兼容模式，并要求标准/兼容两种模式及全部兼容执行记录 |
| 触发 | protocolMode=compatibility 且绑定为 external；没有探测后自动回退 |
| 字段变化 | REGISTER 的 Request-URI 从 sip:路由主机:端口 改为 sip:平台编码@路由主机:端口；Digest 的 uri 和摘要使用该实际 URI |
| 覆盖动作 | 首次注册、401 后认证重发、刷新、注销、取消/失败补偿注销；不改变 MESSAGE 方法或其 XML |
| 保持的要求 | From/To 注册 AoR、GB18030、Content-Length、事务与 SN 关联、正常心跳时钟、认证及资源清理 |
| 依据 | 2016 规范性 J.1/J.3；与 2022 引用 RFC3261 10.2 的模式区分见上表 |
| 可见性 | 操作与出站 REGISTER 报文标记 COMPAT-001；register-uri 检查保留 RFC 条款差异，SIP/业务成功分别显示 |
| 退出与回退 | 注销后显式切回 standard；已有记录保留原模式、版本与兼容项 |
| 验证 | internal/app/mode_test.go、internal/sip/endpoint_test.go、internal/evidence/trace_test.go；外测逐次见下表 |

已观察到的对端缺失 X-GB-Ver 作为独立版本检查结果记录，不能由 COMPAT-001 关闭该检查。没有启用关闭认证、忽略身份/来源、伪造业务成功、缩短心跳时钟或媒体替代等操作。

## COMPAT-002：GB2312 声明的 ASCII 基础查询

| 项目 | 合同 |
| --- | --- |
| 触发与依据 | 外部绑定、显式 compatibility 模式，收到 GB2312 声明；依据两版 6.10 的字符集变化和实际查询失败 |
| 接受范围 | 内容全为 ASCII 的 DeviceInfo / Catalog Query；这些字段与字节同时属于 GB2312 和 GB18030 的共同子集 |
| 解析 | 允许该声明后仍执行原有 XML、身份、SN、字段、顺序、时间、资源和来源校验；不重写原始报文或 Content-Length |
| 输出 | 响应继续使用本项目的 GB18030 序列化，独立 MESSAGE 和 SIP 确认要求不变 |
| 可见性 | 仅已进入兼容解析的入站事务标记 COMPAT-002；结构、模式和原文哈希保留，结构字段同样脱敏 |
| 不适用范围 | 不接受其他编码声明，不扩展到 Notify/Response，不冒称已实现完整 GB2312 文本编解码或全量 2016 协议 |
| 验证 | XML 正反例、原字节不变、结构脱敏、应用层真实查询应答；完整外测按下表逐次记录 |
